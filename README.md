# tambo-hack

An experimental **gesture-driven, generative UI canvas** built with **React + Vite + TanStack Router** and powered by **Tambo**.

The app uses **MediaPipe hand tracking** to drive a “command surface” (a small radial-style UI) that lets you pick a **domain** + **intent**. Confirming an intent spawns draggable/resizable “surfaces” (cards) on an infinite canvas. Some surfaces are rendered locally, and others are generated by Tambo using registered tools/components.

If you want to **start a fresh Tambo project**, use `npm create-tambo@latest my-tambo-app`. If you want to experiment with this gesture-driven canvas demo, clone this repo and follow the steps below.

## Requirements / compatibility

- A modern desktop browser (Chrome/Edge recommended)
- Camera access (for hand tracking)
- Decent lighting (gesture detection is sensitive to camera quality)

## What’s in here

Note: file paths below reflect the current layout and may change as the experiment evolves. If something moves, search for the component name.

- **Interactive canvas workspace** (pan/zoom, drag, resize, combine surfaces)
  - `src/components/InteractiveCanvasWorkspace.tsx`
  - `src/components/interactive-canvas/InteractiveCanvas.tsx`
- **Hand tracking + gesture mapping** (virtual cursor + low-entropy gesture signals)
  - `src/components/SensingProvider.tsx`
  - `src/lib/hand-gestures.ts`, `src/lib/gesture-mapping.ts`
- **Gesture → intent orchestration** (turns gesture signals into prompts/surfaces)
  - `src/components/interactive-canvas/GestureIntentOrchestrator.tsx`
- **Tambo registry** (tools + components)
  - `src/lib/tambo.ts`
  - Components: `src/components/tambo/*`
  - Mock dataset: `src/lib/mock-data.json`, `src/lib/mock-sales.ts`

### How it works (high level)

1. MediaPipe tracks hand landmarks and emits low-entropy gesture signals via `SensingProvider`.
2. `GestureIntentOrchestrator` turns those signals into domain + intent selections.
3. Confirmed intents either:
   - spawn local surfaces rendered by `SurfaceRenderer`, or
   - submit a prompt to Tambo so it can call registered tools and render registered components.
4. `InteractiveCanvas` listens for `tambo:showComponent` events and manages the spawned “surfaces” (layout + drag/resize/combine).

## Quickstart

### 1) Install

```bash
npm install
```

### 2) Configure env

Create `.env.local`:

```bash
VITE_TAMBO_API_KEY=your_key_here

# Optional (only if you’re pointing at a custom Tambo endpoint)
# VITE_TAMBO_URL=https://...
```

Optional: use the Tambo CLI to set this up:

```bash
npm run init
```

This repo includes an `init` script in `package.json` that runs `npx tambo init`. If it fails due to `npx`/network restrictions (or you prefer manual setup), skip it and configure `.env.local` manually.

### 3) Run

```bash
npm run dev
```

Open `http://localhost:5173`.

## Using the app

### Example flows

1. **Analyze product metrics (Tambo-driven)**
   1. Enable **Hand tracking** + **Gesture mapping**.
   2. Show the command surface (open palm).
   3. Select “Product Insights” → “Analyze” and confirm (thumbs up).
   4. A `ProductMetrics` surface should appear, backed by the bundled mock dataset.
2. **Inspect sales performance (local surface)**
   1. Show the command surface.
   2. Select “Sales Hub” → “Inspect” and confirm.
   3. A local sales graph/table surface should appear; use the “Range” control to cycle time windows.
3. **Explain infra health + linked follow-up**
   1. Show the command surface.
   2. Select “Infrastructure” → “Explain” and confirm.
   3. The app will spawn an explanation surface and may also auto-spawn linked follow-up surfaces.

### Mouse / trackpad controls

- Drag empty canvas space to pan
- Scroll to zoom
- Double click to reset the view
- Drag the handle on a surface to move it
- Drag the corner icon on a surface to resize it

### Hand tracking + gesture mapping

1. Open the left sidebar (“Gesture Controls”).
2. Enable **Hand tracking** (this will request camera permissions).
3. Optionally enable **Gesture mapping** to drive the command surface.

Current gesture bindings live in `src/lib/gesture-mapping.ts`:

(The list below is only a summary of the defaults in this repo; `src/lib/gesture-mapping.ts` is the source of truth.)

- **Open palm** → summon/dismiss the command surface
- **Peace sign** → select (cycle options)
- **Thumbs up** → confirm (spawn a surface)
- **Pinch** → drag and drop items

To customize bindings, edit `src/lib/gesture-mapping.ts` (and `src/lib/hand-gestures.ts` if you add a new gesture).

### Gesture Data Explorer

Use the “Gesture Data Explorer” button (top-right) to record short gesture sequences and show a gesture-driven analytics view.

Note: this is an experimental/debugging view (no persistence; UX can vary by browser/camera).

## Extending

### Tambo integration

Tambo is wired up via the `TamboProvider` in `src/routes/__root.tsx`, and the registry lives in `src/lib/tambo.ts`.

To extend what the model can do, add entries to the exported `tools` and `components` arrays in `src/lib/tambo.ts`.

**Important:** this demo uses `as any` in a few places (notably in `src/lib/tambo.ts`) to keep the wiring simple while experimenting. In production apps, avoid `any` and prefer fully typed schemas + tool signatures so you get end-to-end type safety.

This repo optimizes for fast experimentation (gestures + surfaces + prompt orchestration) over perfect end-to-end typing.

### Register new Tambo components

1. Add a component + Zod schema under `src/components/tambo/`.
2. Register it in `src/lib/tambo.ts` under `components`.

### Add new tools

1. Implement a tool function (usually backed by a service in `src/services/`).
2. Register it in `src/lib/tambo.ts` under `tools`.

### Add a new domain surface

1. Add the domain/intents in `src/lib/domains.ts`.
2. Render the surface in `src/components/interactive-canvas/SurfaceRenderer.tsx`.

## Notes

- Hand tracking uses MediaPipe and requires a browser with camera access.
- The included “product” flows are backed by a bundled mock dataset; no external data source is required.
